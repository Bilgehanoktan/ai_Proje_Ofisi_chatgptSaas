## What / why / where / how
- `app/core/event_store/postgres_snapshot.py`: `read_plan_snapshot` owns a fresh, exclusively owned psycopg-compatible DB-API connection. Rejects autocommit, non-IDLE/unknown transaction status. First SQL sets `REPEATABLE READ READ ONLY`, then local statement/lock timeouts. Checks disposable database prefix, isolation, read-only flag and non-super/non-BYPASSRLS role via pg_catalog before and after `inspect_plan_history`. Passes exact plan, expected revision, run pins and optional exclusive budget anchors to existing reader without changing its interface. Always rollback, then close; any setup/query/context/cleanup exception yields HOLD and discards previously returned observations. Never commits, retries, falls back to weaker isolation or returns partial evidence on adapter failure.

## Limits and engineering choices
Connection factory must be trusted, local, disposable, exclusively owned; prefix/role checks are defense in depth, not host identity or RLS policy. Role can still own tables; no proof of tenant isolation. SQL configuration and status protocol are not an actual server test. No independent pin custody, global event ordering, trusted time, success/IV receipt or canonical R03 acceptance. Timeouts 5s per statement and 2s per lock are provisional, not a total operation deadline. Only known psycopg IDLE integer enum is supported; no autocommit or pooled in-flight connections. Never infer authority or live freshness from a successful historical DTO. No actual external effects or writes from the adapter.
