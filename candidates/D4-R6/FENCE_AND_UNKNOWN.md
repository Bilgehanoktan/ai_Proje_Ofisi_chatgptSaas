# D4-R6 — proposed owner integration boundary (not executable)
Existing D0IntentAuthority.claim_and_fence consumes a scope before T1 and locks a separate, non-restored SQLite root through caller commit. It serializes only cooperating root publishers; current wrapper is the witnessed transition path, not universal admission/lifecycle/IAM authority. D0IntentJournal and local_revocation_fence are existing synthetic journal and memory/witness locks. Do not duplicate or widen these authorities automatically.

Proposed ordering to review: protected authentication and canonical full intent -> verified current organization/plan/member/assignment and role map -> retain complete versioned binding -> durable intent claim/stage before mutation -> acquire existing authority root fence and recheck all pinned references/expiry under reviewed publisher protocol -> dedicated PG session same physical role/endpoint, exact ACL/RLS and identity -> original CompanyCoordinatedMapping stream-first, then mapping-specific run/lease/budget locks -> write/verify original T1 -> COMMIT or UNKNOWN -> close dedicated connection -> release fence and independently reconcile retained journal/receipt. No new write adapter in R6. Final identity read must be protected through COMMIT; a read-only R4 check outside transaction is not sufficient.

Revocation linearization: a cooperating publisher winning before fence acquisition must reject the stale intent. If the intent acquires the fence first, a cooperating publisher cannot publish until the protected commit outcome returns. Real authentication, ORG and role-map publishers currently are NOT linked to this root; require owner agreement for versioned publication protocol and lock ordering before claiming atomic revocation. Expiry during commit and crash/restart semantics remain owner decisions; distributed stores and provider calls are not covered. No global deadlock claim. Fail closed on unreachable resolver, stale pin, invalid role or uncertain cleanup.

UNKNOWN/PENDING: preserve consumed intent and durable PENDING/UNKNOWN journal, never reopen the same scope or automatically retry/compensate. Exact independent readback (head, mutations, event, audit, outbox, fence, lease, budget, terminal anchor, company order as applicable) can support review only; absence is not permission. Existing transport CommitOutcomeUnknown is retained. Actual R3 lost-ack test is injected exception AFTER real commit, not network proof. A crash after COMMIT before journal acknowledgement must leave quarantine; actual independent signer/custody remains HOLD. No external effect, real grant or spend.
