## W3/W4 terminal lifecycle and T1
Actual R8 review: lifecycle.inspect_transition returns HOLD for CANCELLED and SUCCEEDED before inspecting the lease; timeout/failed paths require fresh lease even though expired/revoked execution must be fenced. readback_review.inspect_admission accepts ADMISSION only, validates supplied head/lease/reservation but not actual postcommit version or readback authority. LogicalIntent has no target state; RoleObservation has no mutation before/after hash or binding to concrete outbox/event/admission/budget IDs. A terminal result is not proof of delivery or release.

Candidate terminal proposal (non-normative, not an API): scope, run/task/attempt, current and target state, expected aggregate version, before/after digest, admission ID, grant/lease/fence, budget reservation ID, logical effect/idempotency keys, policy/witness epoch, request digest, stop/evidence references, expected terminal reason. Separate readback: new_version = expected_version + 1, committed transaction ID, row identities/digests, committed event and outbox IDs, budget disposition and lease fencing disposition; no receipt may be synthesized from caller observations.
- SUCCEEDED requires artifact/readback/current pin, relevant independent receipt and release status separate; if external outcome unknown, no success claim.
- CANCELLED requires stop authority, cancellation is not proof that effects did not occur; expired agent may not dispatch. Control-plane stop/revoke lane must not depend on dead worker lease; independent authority required before actual design acceptance.
- TIMED_OUT: trusted time and current fenced lease head; old executor cannot write terminal state or renew. Separate owner authority and T1 CAS.
- FAILED: failure evidence and disposition; failure does not imply no external effect. Pre-admission stop may have no reservation or lease; do not invent them, and do not reuse admitted-run role set automatically.
- Terminal run cannot reopen. Retry (when allowed in future) uses new attempt/run admission and distinct fencing, while same logical effect key must retain deduplication constraints. UNKNOWN does not become retry eligibility.
- Terminal state and external-outcome reconciliation are independent dimensions. Stop/fence can be immediate in the future authoritative control plane even while financial/outbox UNKNOWN remains quarantined. Do not close unknown obligations merely because the run ends.

Current admitted TERMINAL required roles = HEAD,MUTATION,FENCE,EVENT,OUTBOX,AUDIT,LEASE,BUDGET. ADMISSION remains 9 roles; ordinary mutation 6. Cancellation before admission, renewal, claim, reconciliation and budget settlement need their own reviewed write/read sets; do not claim equivalence to existing 4 physical tables/5 readbacks/7 entities. No physical table mapping, fifth readback still UNKNOWN. Never issue commit receipt without authoritative local atomic commit and independent consistent readback.

## Outbox and outcome binding
R8 inspect_outbox classifies any send marker or reconciliation ref (even OUTCOME_RECORDED) as UNKNOWN_HOLD; this conservative behavior must remain until reconciliation has evidence. FenceObservation lacks concrete outbox binding. A separate candidate reconciliation record binds tenant/company/environment/run, logical effect key, idempotency key, request digest, event/outbox/commit IDs, claim generation, original and current epoch (distinguish historical proof from live authority), provider correlation, exact outcome/receipt digest and independent issuer, observation source, timestamp/cursor and evidence revision.
Outcomes: CONFIRMED_APPLIED, CONFIRMED_NOT_APPLIED, UNKNOWN, CONFLICT. Only independent authoritative readback may resolve UNKNOWN; negative/absent response alone is not proof. Confirmed applied => no resend; confirmed not applied => no automatic retry; fresh authorization, fence and policy separately. Contradictory or cross-scope receipt => quarantine. F3 remains no external writes. A crash between dispatch and ACK, ACK and local record, or restore must not recreate effect.
## W7 settlement
BudgetSnapshot currently has scope including run and outstanding/recognized totals, but no reservation identity or immutable economic event ledger. ReservationRequest budget_id identifies budget, not necessarily individual reservation. Candidate separate reservation ID, original currency/minor-unit amount, source tariff/version, reserved revision, effect key and economic event ID, outcome evidence ref, settlement version, amount and disposition; preserve tenant/company/period budget scope separate from per-run binding. Unknown amount/outcome retains exposure; no automatic release. Same economic event and same digest -> idempotent historical observation; changed digest -> conflict. Require CAS on shared budget head, atomic settlement with event/fence/audit and authoritative readback; over-reservation or cost exceeding reservation -> HOLD/escalation, no clamping. No FX inference, invoice, payment or accounting post from estimate. Reversal is separate linked economic event. No arithmetic or financial effects run this round.
