# Parallel development / conflict prevention protocol — P10J-04
User direction: apply in all conversations and projects; this repository records its local implementation. Existing CEO-0174 and CEO-0179 scopes unchanged. No main merge, CI, PROD, independent acceptance or new grants.

1. Before work, read CURRENT/NEXT and the relevant design/decisions. Resolve all relevant remote branch HEAD SHAs and actual common ancestor, not an earlier source-only commit. Inventory proposed paths and interfaces. Distinguish source commit and documentation delivery commit.
2. Assign one branch per workstream. UI owns presentation source candidates; core owns runtime, API implementation and database candidates; security owns independent authority design. These are coordination conventions, not enforced leases. No claim about uncommitted work in other chats.
3. Shared manifest, contracts, migrations, architecture, catalog, decisions, progress and handover require explicit three-way review. Never overwrite a shared file based on memory. Each branch keeps revision-specific evidence; shared pointers are reconciled on a dedicated integration candidate, with historical copies preserved. Do not merge divergent core/UI branches without explicit scope.
4. Capture complete untruncated Git trees, compare blob identities and paths; run scripts/parallel_preflight.py with three complete path->Git blob JSON inventories and a verified common ancestor. It is an offline classifier only; it does not verify ancestry, remote HEADs, Git modes, content SHA-256 or authorize a merge. Case aliases, deletes, common files and divergent changes require review.
5. Immediately before moving a branch ref, re-read target and relevant upstream heads. Use non-force fast-forward update with expected parent; abort if the observed target or dependencies have changed. Never force-push or auto-resolve. Record snapshot and expected SHA. Remote HEAD checks are not cross-branch atomic locks.
6. Integration: pin sources, review semantic/API/DB/event compatibility, regenerate combined manifest from exact bytes, preserve prior evidence and decisions, run source, schema, regression, build and browser checks according to existing scope. Never claim independent acceptance from D0 fixtures. Unknown evidence stays HOLD.
7. At completion, read back commit/tree and changed bytes/blob pins, record test environment, failures, rollback, next action and paths. Maintain distinct progress figures. Exact full source ZIP remains required for delivery; if unavailable, explicitly record the blocker rather than label a partial archive complete.
8. Rollback by isolated revert or new branch from pinned prior commit; never reset independent authority, erase claims, or overwrite another workstream. Main remains untouched.
