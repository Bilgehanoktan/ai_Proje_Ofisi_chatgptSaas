## Feasibility
Let E be the earliest bound IAM/session/lease expiration in a trusted clock domain, L the last precommit validation, C the required durable commit boundary. The strict rule requires C < E, not merely L < E. If C-L has no proven upper bound, a valid L cannot establish C < E. PG03 (R5 report blob 846d31387e7ebfd5a71f17d67096b5fc7cac44b7) observed a deferred action at 00:33:22.766904+03:00 after expiry 00:33:21.247536+03:00 and a committed readback row; PG04 UNKNOWN with zero rows is not a universal guarantee.
PostgreSQL 17 documents deferred triggers within the transaction and synchronous WAL flush before success. Neither promises a wall-clock bound. Timeouts, cancellation, 2PC, commit timestamp readback, guard margins and compensation cannot establish the strict property under unbounded process scheduling, clock drift and storage delays. Asynchronous commit weakens durability. A bounded-time substrate would need independently reviewed worst-case clock error, scheduling and durable-write/decision bounds, including crash/recovery; these do not exist in the approved transport. The result is conditional on the present contract and failure model, not a claim that every real-time database is impossible.
