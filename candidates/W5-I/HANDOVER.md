I4: one `ToolReviewRequest` per prospective effect (`TOOL_SAMPLE_REVIEW`), exact tool id/action/input pin and composition digest. Compare owner budget id only as scope/reference; model reservation is not a tool spending grant. Skill resolver uses existing quarantined manifest/source and grant.allowed_tools; both nominated adapters must have diagnostic overlap for this one requested tool, neither is enabled. Existing PEP reviews separately supplied effect/grant/lease/witness; returns DENY even on match. The H consumed-model phase is separate, not preflight: `inspect_consumed_model_binding` compares actual typed W5-D snapshot and W5-H `ReceiptEffectPin` fields including invocation, route, profile, reservation, idempotency, owner pin, membership pin, currency, budget and primary adapter. Reservation issuance transaction and consume transaction are distinct, no inferred equality. `inspect_consumed_model` invokes original H signature/PEP review with the same bound pin/reference; signature match only, no execution/retry/settlement permission. Model and tool fixture grants are alternative diagnostics, not simultaneous valid grants. No proof of absence of replay; H stable keys require T1/Budget atomic enforcement. No H signature is accepted as fresh reservation or tool permission.
