## What / why / where / how
Reuse byte-exact original postgres_session.py (Git blob 8e65e4575a77b11c38c2d2e62ec91fc89d75e23c, 2495 bytes). The existing D5-C-R3 diagnostic used SQLite and a synthetic clock. The new runner is designed for actual PG17.12 with Psycopg, separate fresh loopback database and nonprivileged database owner. It invokes original postgres_transaction with an annotation-only CommitReceipt stub; no T1 role mapping or IAM authority is involved. A disposable table and deferred constraint trigger are created in the isolated database; actual server clock_timestamp is observed before body, just before commit, and in the deferred trigger. PG01 valid observation, PG02 already expired with zero rows, PG03 synthetic deadline passes during deferred trigger and successful late commit, PG04 delayed trigger raises P0001 and original wrapper returns CommitOutcomeUnknown; separate connection readback must be zero. These are expected cases, not observed PG results. The guard is a diagnostic SQL example, not proposed product DDL. A deferred trigger runs before actual durable commit and cannot establish strict expiry at the durable commit point, independent trusted clock/custody, or actual IAM/ORG publisher participation. A server-side rejection observed through the wrapper remains UNKNOWN at its interface; no retries. Readback from another connection is not independent security custody. Official technical references: https://www.postgresql.org/docs/17/sql-createtrigger.html and https://www.postgresql.org/docs/17/functions-datetime.html.
